# R1 技术判定修正与补样

首轮基线调用完成后，原始 `manifest.json` 记录 25 次调用、21 次有效，Skill 指纹前后稳定。原始清单 SHA-256 为 `F595AE9BF9488D72F6B5DF4B39766D5F37EBC59EE835C6A666DBDB34791A375A`，不覆盖、不改写。

逐 trace 复核发现 `ollama/P1_DISCUSSION` 已读取两份规定文件并形成非空终稿，但因同一 `SKILL.md` 同时以相对路径和隔离目录内绝对路径读取，旧解析器把绝对路径误算为第三个文件。该格只做确定性技术重分类，不重跑正文。解析器现将隔离副本根目录内的绝对路径归一为相对路径；读取其他文件仍会进入 `unexpected_reads` 并判路由不完整。

据此，首轮为 22 个可用终稿、3 个真技术无效：`minimax/P1_DISCUSSION` 与 `minimax/C2_CLEAN_REVIEW` 为空终稿，`ollama/P3_MIXED_REVIEW` 为 `ENV_INVALID`。三格不进入质量结论，也不重抽同题；分别用 `S1_DISCUSSION`、`S3_CLEAN_REVIEW`、`S2_MIXED_REVIEW` 三个全新同类任务补样。补样只在对应 provider 运行，基线先于候选，两个臂继续使用相同题面、外层提示和参数。

基线质量复核显示：P1/P2 并不存在跨 provider 的“完全不会讨论”；真正共同缺口是 P3 中三条有效路线误审范围受控的作者解释或否定性证据边界，以及 C2 四份有效稿均把明确标为作者推测、可能性的解释构念列为实质问题。C1 五份有效稿均守住相关与因果边界。候选因此只处理作者分析与经验事实的区分，并保留 P1、C1 作为反向控制。
