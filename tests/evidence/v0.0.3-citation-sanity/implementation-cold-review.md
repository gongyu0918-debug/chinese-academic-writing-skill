# 引用功能实现冷审记录

独立冷审基线：`28899bc`。冷审只读检查入口、引用 reference、审计脚本、测试及 `14c7b99..28899bc` diff，并在临时镜像构造输入。

## 达到三变体阈值并已修复

- Markdown、DOCX、stdin 在不带 `-B` 运行时均生成 `scripts/__pycache__/prose_lint*.pyc`。候选提交 `a3d2519` 由脚本自身关闭字节码写入，并增加三输入回归。
- “2024 年项目”“截至 2023 年 12 月”“样本采集于 2021—2022 年”均被误识别为作者年份引文。候选提交收紧括号式作者年份，并补叙述式“张三（2022）指出”测试。
- “六、参考文献”“参考文献（按引用顺序）”“参考文献列表”均无法切分正文与文后表。候选提交有限支持这三类标题。

## 确定性语义冲突并已修复

原脚本把“句中存在引用标记”命名为 `claim_coverage`，会让仅有元数据或无关来源也得到 100%。候选提交统一改为 `citation_marker_coverage`，文本报告明确它只表示结构标记；有效支持 N/M 仍由证据账本和原文语义核验给出。

## 架构修正

原入口用“释放 reference”描述上下文预算，但同一上下文不会真正卸载已读内容。候选提交改为来源检索另开上下文或轮次，只把紧凑证据账本传入任务叶；入口加任务叶再加任一单独质量层仍不超过 8000 Unicode 字符。

## 未达阈值或保留风险

- 缺失文后条目的定位仍统一报第 1 行；只出现一类复现，按维护约定暂不修改。
- 作者年份识别是保守启发式，复杂团体作者、多个中文作者和学校自定义体例仍可能漏报。
- 脚本只做结构审计，不能验证引文是否真的支持论断，也不能替代全文核验。

冷审实际运行：`python -B -m unittest discover -s tests -v` 在 `28899bc` 临时 clone 中为 80/80 PASS；但上述行为构造仍复现，说明原测试存在盲区。修复后主任务回归为 85/85 PASS。
