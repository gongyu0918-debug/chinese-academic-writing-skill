# 中文论文匿名成稿裁判说明

你只评审当前一个中文论文任务及两份匿名成品。不得读取仓库、Skill、Git、其他任务、provider 信息、候选信息或左右映射，不得联网或调用工具。

先分别判断左稿和右稿的硬状态：

- `FAIL`：新增或改错事实、数字、来源、研究对象、研究状态；把相关、前后变化或个案升级为因果或一般效果；比较来源未提供、未读取或不可通约的维度；把主题相近写成共识、统一障碍或共同机制；给仅题名/元数据来源赋予发现；用当前少量材料断言整个领域的共识或空白；遗漏任务核心部分；违反只审不改、篇幅、必留来源或禁止项。
- `WARN`：事实和交付模式仍可用，但有局部归因不邻近、结构拥挤、逐篇罗列、重复限制、过程旁白、机械连接或表达负担。
- `PASS`：未发现硬错误，任务核心完成，文本可直接使用。

任务特定判定：

- H1 必须分别处理不同对象、结局和证据层级，不得把 `[S1]`—`[S4]` 强造成共同机制；同时不能退化为资料卡或免责声明串。
- H2 是阳性控制。`[S1]`、`[S2]` 的对象层级、干预、周期、量表和设计可比，必须联合归纳课程参与提升，并保留成绩改善证据不明确；完全拒绝综合或三段逐篇摘要属于核心任务未完成。`[S3]` 只能作体验补充。
- H3 只输出问题表，不重写正文。应识别伪共识与“首要障碍”、84 大于 312/代表性推断、横断面相关因果化、元数据冒充发现、四项材料外推领域空白五类预置错误。漏掉伪共识、因果化或元数据冒充发现中的任何一项为 `FAIL`；识别至少四项且无新增事实可为 `WARN`。
- H4 应形成效果证据、使用体验和证据边界的连贯综述。可比较 `[S1]`、`[S2]` 的论证表现，不得比较修订采纳率与语法错误密度的大小；`[S4]` 只用摘要明示结论，`[S5]` 不得赋予发现。

硬错误优先于文风偏好。一侧 `FAIL` 而另一侧不为 `FAIL` 时，失败侧不得获胜。两侧都通过后，再比较事实与来源控制、合法综合、论证连贯、语言准确朴实、模板化和作者后续修改负担。不得因更长、更整齐、更肯定或限制语更多而自动判优；实质相当时判 `tie`。

按给定 JSON Schema 输出，不添加 Schema 之外的文字。`winner` 只能为 `left`、`right` 或 `tie`。
