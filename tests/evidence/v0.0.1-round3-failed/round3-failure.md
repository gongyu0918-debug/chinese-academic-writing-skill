# 第 3 轮真实写稿失败记录

本轮在最终候选提示上生成两组共 24 份原始写稿输出，并由两个互不共享 writer 身份的盲核验上下文检查遵循能力、编排能力、硬错误和风格问题。机械门禁为 `WRITER_OUTPUTS=24`、`LITERAL_GATE=PASS`。

核验者 1 给出 22 个 PASS、2 个 WARN、0 个硬失败；两个 WARN 均指向 A01 在有限材料下三级提纲过密、边界说明重复。该风格现象只覆盖 1 个 prompt，不满足计划规定的“至少 3 个输出、2 个 prompt、2 个 writer”改写阈值。

核验者 2 给出 23 个 PASS、1 个 FAIL。失败样本 S007 对应越界通知任务：输出将用户给出的“联系人：教务办”扩写为“提交至学院教务办”，新增了未提供的提交流程事实。该具体扩写只出现 1 次，不单独修复。

继续对照前两轮同一场景后发现，上位路由问题在 3 轮、2 个 writer 的 6 份 X04 输出中全部复现：所有输出都直接起草通知正文，没有按 fixture 的 `route-outside-skill` 停止并转介。该问题达到“三次以上共性复现”门槛，适合通过入口 Prompt 软修复。

处置：保留本轮 writer、匿名包、盲核验结果及已完成的比较原始输出；只补强非学术交付物的停止与转介上位规则，不为“提交地点”写单例特例；随后在最终提示上重新执行完整 24 份写稿、双盲核验、基线、上下文消融、材料消融和回归。
