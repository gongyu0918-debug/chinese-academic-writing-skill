# 本轮规则审计的主审取舍

原生只读审计完整报告见[rule-audit-raw.md](rule-audit-raw.md)，实际读取7份当前Markdown（入口与6份reference），未读运行脚本、历史证据或候选；模型/effort见native-session-models.json。审计建议是待判断意见，没有直接进入产品。

|条目|主审判断|处置及验证缺口|
|---|---|---|
|1 已读材料与待核验来源|确有对象/状态交叉解释风险，但“读到内容即可用”的新定义过宽：已知身份错配、有更正或撤稿问题的全文也可能已读；不能仅按访问层级放行。作者原始记录与外部文献还须分开。|本轮仅试原始材料/外部来源范围候选，三批实际写稿没有稳定收益，并复现硬交付失败，取消。J四稿仍排除已知DOI身份冲突，这是局部控制，不能证明审计提出的另一版定义安全。|
|2 开题“进行中”归类|入口17行已有进行中状态，开题7/19行却将归类压为已有、拟开展、预期，如何保留正在实施部分没有直接示例。全局不得改状态已提供约束，因此不能推定必然把正在做写成尚未做。|保留文本边界候选。下一验证需给已完成设计＋正在预调研＋尚未正式发放的同一事项，检查正文能否分别保存，先测当前规则，再只作局部消歧；本轮未运行这项实验。|
|3 系统综述满足条件后产物|“才可按材料处理”说明必要条件，不充分说明真实完整由谁确认、可否转写流程和计数，以及何处到方法学判定为止。审计中的两种解释不能都视为现有授权。|留作范围说明待验证，不直接扩展为完整系统综述写作/PRISMA生成能力。需要真实可读筛选记录和不完整/冲突对照，分别测转写计数与禁止补方法学判断；本轮未验证。|
|4 状态文件授权|long-form9行是用户授权写当前项目或要求跨轮保存，不是操作系统可写。只审任务与保存状态可以并存，当前明确边界又优先。审计建议将所有项目写入授权降为逐次状态授权，会实质改变既有功能，并非必要消歧。|不采纳收紧建议。本轮两轮明确授权保存，真实落盘；独立审计仅授权audit-report.md，原正文/状态/简报3文件字节未变，rules也未变。没有覆盖仅宿主可写、用户禁建状态或所有授权组合。|
|5 转引标注对象|“准确转述仍可按其来源使用”的“其”可能指实际读到的综述，也可能指未读原始研究；同段已有回溯原始研究，但没有明确转引展示方式。|保留文本边界候选。需要只有二手综述、未读原研究的受控材料和真实书目，核对来源ID、是否冒称核验、文后清单；本轮B/J检查了层级/身份，没有测试转引，不能替代。|

主次详略在交叉阅读中没有新的确定冲突。实写G/H保留会改变判断的反证和必要限定，但仍有重复、ID遗漏和无依据“没有重复观测”；这更像已有约束执行不稳定，不据此加固定主次比例或要求背景逐项报缺。

磁盘日期误记也已有不可变事实/数字约束，不立即加一条“不要猜日期”。先以不同日期类型和多轮保存验证普遍性，再考虑具体而不重复的最小修订。
