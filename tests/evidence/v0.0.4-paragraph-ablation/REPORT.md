# v0.0.4 段落自由度冷审与消融报告

## 结论

本轮完成了规则冷审、指定公文任务复核、高校与社区方案对比、三任务三臂写作消融和一次预注册硬边界修复。候选规则消除了固定句序、句数、句位、收束句和等长段落要求，同时保留事实、数字、样本身份、引用、因果、否定范围和研究状态硬门禁。

现有证据只支持“概念修正且修复后无已知硬回退”，不支持“整体优于提交态旧 Skill”。修复后的候选三题均通过硬边界，但两名裁判都认为旧 baseline 在 T1 的论证紧凑度、重复控制和直接使用成本上小胜；初轮六次逐题排序中，baseline 居首 4 次，candidate 居首 2 次。该候选不得据此发布为已验证的质量全面升级。

## 冷审问题与处理

| 冷审问题 | 处理 |
| --- | --- |
| 文风共性阈值错误覆盖引用、因果等硬错误 | `SKILL.md`、`citation-research.md`、`HANDOFF.md` 改为经复核单例即阻断 |

| 段落主导任务、章节收束和 ANTI-AI 层可能形成重复兜底 | 改为最小可充分论证单元；收束与过渡按需要出现；ANTI-AI 不再默认加载 |
| 论文文体规则跨学科过度统一 | 增加理论、文学历史、法学、实证和理工的线索分流，明确只作线索、不作模板 |
| 范文仿写可能搬用观点和来源 | 只校准术语、引证方式、限制语和节奏；观点与来源仍须单独核验 |

| Markdown 与默认上角标契约冲突 | 富文本用上角标，纯文本和 Markdown 用 `[1]` |
| `citation_audit.py` 把“本项目（2024）”等普通名词误作作者 | 增加普通研究阶段/期间/期内识别，并保留“未来学习项目（2024）”与真实作者的正例 |

## T1 窄修复

修复前冻结 `repair-plan.md`：入口只增加“样本称谓按原文保留，不从场景推定身份”，只生成一份 T1，不重复采样。writer 实际报告读取当前 `SKILL.md` 与 `references/academic-writing.md`；唯一复测保留“18 名访谈对象”，非空白字符 509，格式合规。

两份重新匿名、内嵌正文的包得到一致结果：

- baseline：PASS，两个裁判均排第 1；
- candidate-repair：PASS，两个裁判均排第 2；
- no-skill：FAIL，两个裁判均排第 3。

因此硬回退已经关闭，但 T1 的轻微质量回归仍存在。裁判共同指出 candidate-repair 的“具体座位区位与高低使用率同时出现”较空泛，限制语略有重复。该现象只在一个任务、一个输出中出现，未达到文风 Prompt 的共性修改阈值，本轮记录而不继续追补。

## 剩余风险

1. 只有三个实证类段落任务和一次窄修复，尚未覆盖理论、法学、文学历史、理工长章节及真实导师模板。
2. baseline 在本轮仍整体更稳；在更大留出集证明不输旧版前，不应发布“质量提升”结论。
3. v0.0.3 引用生成旧证据仍为 2/4 硬失败。本轮修正阻断规则和结构扫描误报，但没有重跑引用生成，不得声称引用语义已稳定。
4. `prose_lint.py` 的绝对阈值未按章节长度重新校准；通过将 ANTI-AI 层改为按需加载降低影响，但脚本命中仍只是候选。
5. 初轮匿名 map 与包位于同一证据目录；裁判被明确限制只读包文件，但没有独立文件访问审计。修复轮改为正文内嵌并使用新裁判，仍应把匿名隔离看作流程约束而非安全边界。
