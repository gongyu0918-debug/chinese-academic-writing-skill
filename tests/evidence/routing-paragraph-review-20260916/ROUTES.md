# 最终路由逐边审查

基线：`46e7532c43c7f27a9a3a2f2d66bc37907064c428`。最终规则快照：`snapshots/candidate-final-skill/`。本表为逐条阅读后的人工语义审查，不是 Python 路由门禁。历史逐边表及七项缺口保留在 `audit-history/route-audit.md`，其作者在模型纠正前使用了 Astra，故只作初查记录；正式冷审采用 Qwen Max 与 Kimi K3 `max`，主维护者逐项回查原文。

W = 普通论文，P = 开题，L = 独立综述；C = 来源与引用，G = 长稿，A = ANTI-AI，V = 宿主独立复核者。W/P/L 是三个主叶，C/G/A 是共享辅助页；V 是宿主角色，没有新增第四主叶或代理程序。位置以下用实际文件及章节名表示，避免把随编辑漂移的旧行号当作最终定位。

## 十二个主叶模式

各模式均从 `SKILL / 四维路由` 可达；W/P/L 的入口分别在三个 `academic-*.md` 页。

| 边 | 模式及所需材料 | 完成出口 |
|---|---|---|
| W01 | 普通论文提纲：问题、材料、模板 | 按章节任务交结构，不预定结论 |
| W02 | 普通论文起草：本节问题、证据、允许判断 | 本轮正文 → V → 有依据的局部修改 → 交付 |
| W03 | 普通论文修改：目标稿、范围、更正依据 | 范围内改稿 → V → 交付 |
| W04 | 普通论文审稿：原稿与可用依据 | V 的具体意见；不代写全稿 |
| P01 | 开题提纲：已知方案、学校栏目与状态 | 明确的提纲专节；每节职责与材料缺口，不扩写正文 |
| P02 | 开题起草：已有/拟开展/预期工作 | 当前栏目正文 → V → 交付，不升级完成状态 |
| P03 | 开题修改：计划、旧稿、已确认更新 | 更新指定位置 → V；冲突可交意见后结束 |
| P04 | 开题审稿：问题、目标、内容、方法、进度 | 结构与研究状态意见，回入口只审接口 |
| L01 | 综述提纲：来源层级、范围、组织轴 | 明确的提纲专节，主题与来源对应，不假造共识 |
| L02 | 综述起草：可用来源、比较关系 | 就近 ID 的综合正文 → V；仅按交付需要展示来源表 |
| L03 | 综述修改：原稿、来源映射 | 保留归因的范围内改稿 → V → 交付 |
| L04 | 综述审稿：原稿、原文/摘要/元数据 | 支持、错配、外推或伪共识意见，回只审接口 |
| L05 | 系统综述过程 | 实际协议与检索筛选记录 | 有记录按材料处理；无记录不制造流程、数量，不跳入未实现的协议 |

## 辅助层与返回边

| C01 | 显式授权公开检索/核验 | `citation-research / 授权与范围`；同一任务、范围不变时跨轮沿用授权 |

| C07 | 核验后还需写作/语言复核 | 紧凑证据与未决项 → 所属主叶 → V/A；不物理卸载上下文 |

## 段落、独立角色与终止

| 边 | 输入或条件 | 返回、交付与停止 |
|---|---|---|
| N01 | 用户只写一段或逐段推进；已有提纲/相邻内容 | 所属主叶；当前任务、证据、承接、后段范围作内部简报 |
| N02 | 当前段成稿 | V 复核当前范围 → 主写者有限修改 → 本段交付即停 |
| N03 | 后续继续 | 从已交段的下一任务接续；保留事实、引用和状态，不重新生成前段 |
| N04 | 缺相邻原文且确实影响承接 | 只问所需片段；可独立写的部分继续；无无条件逐段确认 |
| N05 | 一次要求多段或一整节 | 完成本轮明确范围，不强制每段停工等确认 |
| V01 | 正文起草/修改后，或用户明确要求审稿 | 可用且未被禁止时原生唤醒未参与起草的 subagent；沿用授权，不逐稿询问 |
| V02 | 已有独立审稿者正在审用户原稿 | 该角色直接承担 V，不再派生复核者 |
| V03 | 交接 | 请求、稿件/限定片段、相邻上下文、材料定位、主叶、必须保留项 → 只读意见 |
| V04 | 意见返回 | 主写者处理有依据问题；通常一轮，只有新实质问题才复看受影响处 |
| V05 | 复核不可用、失败、被禁止 | 可交付任务继续；不声称完成独立复核；只正文时不附过程说明 |
| O01 | 只审 | 位置、严重度、问题、依据、建议；形式服从请求和文本规模，交付即停 |
| O02 | 只正文/改后文字 | 只交相应文本，不附路由、字数自证或检查流水；材料不足仍按材料出口 |
| O03 | 允许补充建议 | 只列有内容、与本轮有关的建议；建议不冒充已做研究 |
| O04 | 同时要审和改 | 先审后改已确认问题，按要求交意见/改稿/两者，本轮结束 |

## 完备性结论及实测限制

上述每条边均有触发、输入和可终止出口；文件指针均落在既有三主叶、三辅助页与三脚本。没有发现必然死循环、死锁或整条不可达叶。基线真实缺口是 P/L 提纲出口、离线 C、上下文“卸载”措辞、逐段边界与 V 角色连接；不是三主叶全部失效。

来源失败交问题、缺原文请求补充、未授权写盘时留在上下文、工具缺失继续交稿，都是正常终止或交回用户的出口，不要求每条路径强行产生正文。用户的新一轮请求不是内部循环。V 不递归，主写者只复看受影响处，删除式复核一次结束。

实际读取与执行仍有差异。`native-formal-routes` 覆盖 T1–T9 和混合任务，后续 `native-v3-final/T10` 覆盖提纲联审正文，`native-final-closure/empty_review` 验证缺原文出口；并非每个组合都有独立实测。MiniMax 在 r3 及 r4 重试的 `fresh_review` 都只读 SKILL，未加载主叶/A；其入口读取成功不能算辅助层可达验证通过。Qwen 实际读取并完成过相关路径，且有独立子代理记录。最终仍不宣称所有模型遵循率 100%。

完整真实命令见各 `native/*/*.result.json`，实际角色元数据及可见审稿意见见 `delegation/`。路线判断和质量裁定分开保留，不以文件名出现或一次响应成功决定好稿。
