## 结论

三类专项叶都有清楚的入口，6 份 reference 均有上游引用，未发现必然不可达的整份叶子，也没有足以认定“任何合规执行都会进入无限循环”的规则。当前不能称为每个连接都已闭合：两份叶子缺少提纲模式落点；来源阅读与联网授权耦合，造成离线引用审查的路径歧义；跨阶段“释放 / 不同时加载”的规定依赖未定义的上下文能力。逐段成稿的范围控制与独立宿主复核属于用户本轮明确提出、当前没有完整连接的新能力。

## 需要修正或验证的连接

### R1 / P2：开题和独立综述的提纲模式没有专项落点

- 位置：`SKILL.md:17` 声明四种模式；`academic-writing.md:19-25` 有独立提纲分支；`academic-proposal.md:11-32` 和 `academic-literature-review.md:17-35` 仅列三种模式。
- 问题：入口按文种把任务送达正确叶，但在材料充分、明确“只要提纲”的情况下，后两叶只能借用一般任务链和来源组织原则，没有模式级完成条件。它们并非完全不能给提纲：开题 `:9`、入口 `:30,:33` 确实提供材料不足时的框架出口；问题在于“材料充分的正常提纲”没有对应分支，容易误走起草或把结构建议写成已经确定的研究设计。
- 请求例子：`下面是已确认研究问题、访谈方案与学校开题模板，请只列开题报告的二级提纲，每节一句职责，不写正文。`；`这六篇摘要和来源 ID 已给齐，请按争议轴给独立文献综述提纲，不写正文。`
- 最小修正：给两叶各补简短“提纲构造”：按本叶任务链或来源比较轴组织栏目；标明可用材料与缺口；仅交付提纲并结束。无需增加第四叶或机械章节模板。
- 真实写稿判据：交付保持提纲；不串入普通论文叶；不代拟研究安排；综述标题不能预写未被来源支持的共识或结论。

### R2 / P2：来源层将“读规则”和“联网”绑定，离线审引与默认引文格式存在路径歧义

- 位置：`SKILL.md:37,:49,:62`；`citation-research.md:3,:11,:23-37`。
- 问题：来源层开头称“显式授权后使用”，并规定只有用户明确要求“联网检索、补充或核验学术来源”才“读取并联网”。因此“核验”究竟包括使用用户已给全文的离线核验不够清楚。若包括，则读取可能被误当成联网许可；若仅指联网核验，则离线用户到不了该层的逐分句来源映射、有效支持覆盖口径和默认顺序编码规则。入口已有一般引用审查，因此不应称为全部离线审引不可达；缺口是详细来源能力与联网权限没有分离。
- 请求例子：`仅使用这两份完整 PDF，禁止联网。逐句核对我的讨论段及引用是否被原文支持，保留必要修改。`；`根据我给的三篇全文写一个比较段，默认格式引用，不检索。`
- 最小修正：按当前任务是否需要来源核对决定读取；按用户授权独立判断能否联网。若来源已给齐，读取相同证据核对规则并走离线分支；联网分支才做检索和出版状态补查。参考文献样式可在入口保留简短默认规则，或让离线路径可达来源层。
- 真实写稿判据：不联网也能完成限定范围的来源映射；不把未核验出版状态写成正常；无外部权限时不虚报检索；正文引用位置贴近被支持论断。

### R3 / P2：阶段切换可理解，但“释放上下文”没有可执行能力或回退说明

- 位置：`SKILL.md:25,:62`；`citation-research.md:11`；`long-form-consistency.md:5,:38`。
- 问题：混合任务要求依次读叶，来源阶段结束又要求“释放本 reference”，长稿同时涉三层时要求分轮次且“不同时加载三份”。普通宿主可在一个上下文内按阶段改变关注规则，却通常不能移除已读的消息。当前没有说明“不得同时加载”指当前生效职责还是物理上下文，也没有把新上下文交接绑定到宿主可用能力。严格按物理含义执行可能在第二层开始前等待无法实现的释放，或为满足隔离而丢掉证据。这是条件性卡住风险，未证明必然死锁；入口的“另开上下文或轮次”给了合理解释空间。
- 请求例子：`核对这两章的术语和结论，联网核验三处引用，再压掉模板腔；一次交付修订稿。`；`先给开题提纲，再根据已给来源写一份独立综述提纲。`
- 最小修正：用“当前阶段只执行本阶段职责，交接紧凑状态”替代物理卸载要求；宿主支持独立子任务时分别执行，不支持时同上下文按明确顺序完成。每一阶段列产出和下一步；来源失败可转未完成清单，不能无限重搜。独立复核可自然承担最后质量阶段。
- 真实写稿判据：无需虚构新上下文或要求用户另开会话；换叶后不把上一文种栏目带入；证据账本和不变量不会在切换中丢失。

### R4 / P1（本轮需求缺口）：逐段成稿没有明确的范围、交接和停止协议

- 位置：`SKILL.md:42,:51,:56-57`；`academic-writing.md:9,:17,:29-31`；`long-form-consistency.md:25-41`。
- 问题：现有规则支持按论证自主成段、单段润色和按节续写，但“单段语言任务”不等同于“只写下一段”。一方面允许动作跨段展开；另一方面状态包的最小任务是分节简报。段落轮次的本段任务、前文已完成内容、留给后文的任务和成段即停没有显式连接。跨轮单节可进入长稿层，而跨轮单段不需其他章节时是否进入，又受入口相邻句不同条件影响。用户优先级能约束明确的一段请求，但不能替代默认续写状态。
- 请求例子：`按这个提纲一段一段写。现在只写讨论第一段，说明两组材料的共同点；差异留给下一段，结论先不写。` 下一轮：`继续第二段，只比较差异，别重述第一段。`
- 最小修正：在入口将输出单位与操作模式分开，新增单段/逐段模式语义说明；最小段落状态包括本段任务、可用证据、已完成内容、后续保留任务。只完成本段后停止；用户说继续时承接已确认状态；没有状态则请求最少必要前文，不猜写下一段。无需为每段固定句式或强制磁盘文件。
- 真实写稿判据：每轮恰好交付要求的段落；不提前写后段比较、对策或结论；第二段实质推进而非重复第一段；保持证据、来源 ID、范围与研究状态。

### R5 / P1（本轮需求缺口）：质量复核没有宿主独立复核者的入口和返回边

- 位置：`SKILL.md:58,:66-68`；`academic-writing.md:49-54`；`academic-proposal.md:38-42`；`academic-literature-review.md:41-46`；`anti-ai-writing.md:5-11,:52-54`；`long-form-consistency.md:49-60`。
- 问题：当前全部“复核”默认可由同一写作执行者继续完成，没有将成稿交给宿主 harness subagent 的连接。ANTI-AI 的触发、纯检测输出和最多两遍的局部修改逻辑有定义，但复核角色、只读职责、回传意见、作者/主写作者采纳与终止没有定义。这是本轮要求的新能力缺口，而非既有文本承诺了却失效的功能。
- 请求例子：`只根据这组材料写讨论段，成稿后请独立复核 AI 味、结构、逻辑、重复和流水账，最后只交正文。`
- 最小修正：成稿后由宿主可用的独立 subagent 接收用户范围、当前稿、必要证据/相邻上下文；以位置、问题、依据、建议回传，不整篇重写；主写者仅修已确认问题，影响事实的改动按来源复核。明确返回/停止规则。宿主没有该能力时说明未做独立复核，不冒称已完成，也不能等待一个不存在的必需工具。
- 真实写稿判据：可见不同执行者实际复核记录；能识别结构/逻辑/重复/流水账，而非只扫禁词；没有问题不强改；独立复核失败或工具缺席不伪造通过记录。

## 可优先保留的既有正确关系

1. 文种按所在交付物分流，论文综述、开题述评和独立综述的归属清楚；无需重构成更多叶子。
2. 无材料的替代交付、版本冲突报告、来源失败未完成状态都已提供可停止出口。不要为了“每条路径必须产正文”把这些出口删掉。
3. ANTI-AI 已有无明确问题不改、只检测不改、删除式只做一次、必要否定保留等规则；问题在于实际执行质量和角色分工，不宜用更多词汇黑名单代替。
4. 长稿层未把磁盘状态文件设为前置必需；现有无保存授权的上下文状态回退应保留。
5. 三个 Python 脚本在产品路由中均被表述为可选、只读候选工具，而非语义是否正确的裁决者。是否卸下仓库里的 Markdown 文句断言，应由维护测试边界审查另外确认。

## 建议的真实写稿验证顺序

先验证 R4 的连续两轮段落范围与 R5 的独立复核，再用 R1 的两份提纲检验不误进正文，用 R2 的离线全文比对检验引用，最后用 R3 的多交付物/多层任务验证顺序与终止。每例保留原始请求、材料、原稿、候选稿、独立意见和可归因差异；判定以稿件是否完成当前任务且保持证据边界为主，不把规则出现了某句当作通过证明。

## 补充核对：来源语义与段落交付

### R6 / P2：有限作者分析进入来源层后的判定口径不够清楚

- 位置：W `academic-writing.md:13` 与 C `citation-research.md:20,:25`。
- 独立判断：这是需要真实稿件验证的阶段口径冲突风险，不宜直接判为必然矛盾。W 明确允许有材料与普通常识支持、表明作者判断的有限解释；C 的直接目标是带引文论断与来源支持，按合理范围理解可以兼容。但 C 把段首、过渡、段末综合一律纳入待核验论断，写后只允许“支持”直接保留，未单列作者分析的判定方法，可能把合法推断误判为来源没有说过的新增事实。
- 请求例子：`依据已提供行为记录和访谈材料写讨论段，保留“可能”强度的作者解释；再用同样材料逐句核验，不能因解释不是原文逐字说过就删除。` 宜用上一轮已经验证成立的有限分析样本回放，而非另造一个有争议构念。
- 最小修正：分别核对来源所报事实/结论与作者有限分析；后者检查材料基础、推断关系、对象/范围/状态和措辞强度，而不是要求来源逐字作出同一句归纳。必须继续禁止凭两个局部关系拼出未检验整体中介或因果路径；C `:18-20` 的具体路径边界不能借此放松。
- 真实写稿判据：同一个合法有限分析在加载来源层前后不会因“原文未逐字说”被删；伪造结果、改对象、强度升级和未经支持的整体路径仍能被指出。

### R7 / P2：独立综述“来源状态”没有明确服从段落交付范围

- 位置：L `academic-literature-review.md:11-13`；入口 `SKILL.md:36,:68,:70,:72,:74`。
- 独立判断：不能说叶子有效地压过了用户“只交正文”；入口优先级和交付规则已经明确，严格解释应当不附表。但 L `:11` 接着要求来源“列为”实际使用、另列提及未用于观点，容易被理解为每份综述输出必须附来源状态清单。对于用户只要一段比较文字、或分轮只写本段的任务，这是一条可触发格式外溢的强措辞。
- 请求例子：`只根据来源 A 和 B 写一个独立综述比较段，仅输出这一段，保留 A/B 就近标注。` 可同时放一条仅有元数据、只能用于报告冲突的 C，看模型是否擅自追加状态表。
- 最小修正：内部始终保持使用状态一致；仅在用户要求或交付允许来源说明时展示清单，清单也限定在本轮已处理范围。用户指定来源 ID 的正文就近标注继续保留。
- 真实写稿判据：只段落任务只交该段，来源 ID 就近保留；不附状态表或清单；未使用来源不会被编进观点或全稿参考文献。

## 对拟采用的复核结构的边界建议

宿主提供子代理时，一次只读独立复核可以作为清楚的终端阶段：评审只回问题，不再派评审；主写者处理已确认问题并结束。这样能消除递归复核链。无子代理仍可完成用户文本、但不得声称完成独立复核；无需因工具能力缺席阻塞起草。复核层应收到本轮段落职责与必要相邻上下文，否则评审容易把“后续才展开”误当本段缺陷，进而诱导越界补写。
