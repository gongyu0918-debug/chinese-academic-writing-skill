# 主维护者的材料复核与取舍

这份记录按原始材料、实际稿件和调用轨迹裁定。匿名审阅原文完整保留，但其偏好票不自动成为结论。`invalid=[]` 只表示驱动取得了返回且观察到入口读取，未判断事实、篇幅、叶子加载或写作质量。

## 合入与取消

| 项目 | 处理 | 能支持决定的证据与边界 |
|---|---|---|
| 四模式、离线引用、混合任务、层间返回/停止 | 合入 | 静态逐边审阅及 Qwen/Kimi 冷审未见阻断；实际 T1–T10、缺原文任务有交付。MiniMax 并非每次实际读取辅助页，不能声称全模型遵循 |
| 按段推进、原生独立复核 | 合入 | Qwen 的起草→另一个原生子代理→删去重复尾句→交付链有独立上下文和精确便宜模型记录；同一 session 的下一段继续保留首段原样。不是仅给接口建议后声称已验证 |
| 按结果段/讨论段职责判断结构 | 合入 | 全新只审任务及反控中，合格结果段可原样保留；不是见数字排列就要求补原因。MiniMax 跳过辅助页的审阅不能用来归因该规则 |

| 在复核第 1 步再强调区分冗余表达（r6 探针） | 取消 | Qwen/MiniMax 的四个双臂配对保住 HN_guard 的必要双否定，但 N2 仍留冗余；MiniMax 候选还把两段合成一段、推定单一机构。最终未采用该句 |
| Python 测试职责 | 合入 | 53 个语义/文案/历史判词断言删除，13 个混合测试拆分；166 个相关维护测试保留并通过。三项运行脚本字节不变，历史证据不改写 |

最终规则以 r5 的路由、交付和复核修正为基础，恢复基线 `anti-ai-writing / 高频句式与词组` 整段。其他关于独立角色、结构先行、正常结果报数的修改保留。r6 第 1 步不进入产品。所有候选快照保留，不能将 r2/r3/r4 的结果谎称来自最终字节。

原有“两个以上否定分句”是人工定位线索，后文仍要求结合材料保留必要否定；它不是 Python 准入阈值。实测没有证明删掉这段比保留它更好。当前仍有便宜模型保留多余否定，记录为后续具体缺陷，不宣称已解决全部 AI 味。

## 可以回看原句的收益

`native-v3-final / m0-P2_proposal-candidate`：题面只写“已有研究基础”，后段才讨论研究方法。父代理草稿尾部为“研究对象的范围由此保持稳定，为下一步逐件比较提供了材料前提”。原生独立复核者发现这与前面的固定比较范围重复，并把收束挂到后段任务；主写者按意见删去，段落结束于“经导师同意，这24件藏品说明文本确定为本课题的研究对象。”材料的年份、24件对象、已核对与尚未比较状态均保留。

父 session：`01a0a71c-02a9-78d3-a4ad-ed97c76fe9c2`；子 session：`01a0a71c-f548-7963-be9c-0254ee212517`。两者均为 `alibaba-token-plan/qwen3.8-flash` / `max`，spawn 明示 `fork_turns: none`。交接与可见意见在 `delegation/native-v3-final/`。独立复核者同时给了删尾后的完整段落示例，超过“只给必要局部改法”的理想简洁程度；不能把它描述为完美的角色遵循。

同一父 session 随后用 `exec resume` 继续研究方法段，首段文件 SHA-256 未变；新段只写拟配对对读、记录顺序、比较同异，分析类别继续待讨论，没有进度。Kimi 对该续段未发现硬问题。MiniMax 的续段也没有重写前段或提前写进度，但添加了“与导师进一步讨论”，题面只说“仍待讨论”；这是未提供的讨论对象，不能因符合常见开题情境而冒充已有安排。

离线 C：`native-formal-routes/m3-T4-candidate` 能保留“进度可见性可能为部分受访者判断是否继续询问提供线索”这一有材料基础的作者解释，并指出 A+B 无法共同证明模板通过进度可见性减少等待时间。它输出过长、附路由旁白并在引用标号解释上过度推断，故只认定目标语义区分成立，不把整份意见判成优质交付。

最终补出口的 T9 中，Qwen 在 80 字限制内保留 `[7]` 和有边界的作者分析，没有追加参考文献表；但加了字数前言。MiniMax 只保留了摘录事实、删掉作者分析，并将“称能减少”压成“称减少了”，存在强度偏移风险。离线与编号路径可用，不等于分析保留已在各模型稳定。

## 不采用的冷审判断

1. **不能把底稿所有否定都提升为不可删事实。** 首批 Qwen Max 的匿名审阅把“手续未减、窗口未增、资源未整合、改革成效不承诺”逐项当作必要限制。N2 的原始记录只说明 12 人咨询体验、8/4 分歧、未测等待时间和无跨机构样本；任务明确要删多余重复。不同否定对象并不自动具有独立论证价值。删除不相关对象不是事实损失；把“资源整合”改成“资源增加”则确实改变了否定对象，二者必须分开判断。
2. **复核者建议也受证据约束。** `native-v4-review-route/m3-fresh_review-baseline` 用“反馈后”“即时反馈”解释 13/7 结果，题面没有反馈机制。`native-v4-technical-retry/m3-fresh_review-candidate` 仍建议“完成率上升”，没有第一次计数。Kimi 认为后一份示例不添新事实，主维护者不采纳这点；两份均有意见越界，不能只按偏好票把候选算作通过。
3. **正常结果段不是缺少解释。** 20 人中 13 人补齐、7 人遗漏可作为结果报告。第一轮某些评审要求补基线、原因、判定标准或文献，超出当前材料与段落职责。可以指出全文研究设计可能需要更多说明，但不能把未提供数据写成必须在该段补入的事实。
4. **数理和研究状态须回读原题。** 4 天相对 2 天“高 1 倍”在算术上成立，不当作数理硬错；用户已明示计划变化时，“取消原拟访谈”是研究安排事实，不是模型制作旁白。将“已核对标题与顺序”写成“两版完全一致”则是未经提供的核对结果，确为硬问题；它出现在 r2 的 MiniMax P2 基线，r3 该候选没有同样错误。
5. **不因模型知识时间误改规范年份。** 两位 r2 冷审对 2025 版标准存疑。主维护者查了国家标准官方页面：GB/T 7714-2025 自 2026-07-01 实施，GB/T 7713.1-2025 自 2026-02-01 实施，保留当前年份。仅核对元数据，未声称完整读取标准条文或完全符合。
6. **部分审稿意见仍过度限制。** Qwen 把“全校、所有任务、长期”简化为同一边界，实际上是总体、任务与时间维度；它们在该题是外围免责声明，删除的理由是与当前判断无关，不是三个维度本来等同。MiniMax 在正常结果反控中把“选对/误选”的正反并列当成不齐，也不是必要修改。
7. **最终 Kimi 也重复了保全外围否定的误判。** `review-negation-final-kimi` 将删除手续、窗口和资源整合视为丢失必要限制，主维护者不采纳；访谈未测某项不等于论文应逐项列出所有无法证明的事项。“咨询”在此改为“询问”也未必是专业术语漂移。最终 N2 的真实问题仍是多余否定、重复、个别模型推定单一机构；不是删掉无关限制本身。

最后一轮 Kimi 对完整最终七份规则给出“规则文本无阻断问题”。两点低级别建议（“不解释”与审稿字段优先级、课程作业的综述归属）已由现有用户优先级和按最终交付物路由覆盖，没有新的误路由证据，未继续增补规则。

标准官方页面（2026-09-16 核对）：[GB/T 7714-2025](https://std.samr.gov.cn/gb/search/gbDetailedCNF?id=4507EFE13D37CB6AE06397BE0A0A601F)、[GB/T 7713.1-2025](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=36C05B5738C54D42B4B262525320B52F)。

## 竞品：具体借鉴与未采用

- `gov-doc-skills` 的“每个段落必须有一个主要功能”：取其当前段主要职责，结合用户前后段范围落实为逐段交接。论文同一段仍可包含证据、解释与必要限定，不强制一段只做一个动作。来源与固定 commit 见 `audit-history/competitors-sep16.md`。上述 Qwen 段末删除和同会话续写是实际例子；不是竞争规则本身已证明优于本仓库。
- `humanizer-zh-tw` 对否定对象的关注值得测试，但本仓库已有相关判定。更短的改写及 r6 单句未证稳定收益，取消；“把尾部否定补成完整子句”也未引入，补语法不能证明其有论证价值。
- SkillHub `govwriting` 的合并同类项只在后文没有新增推理时有用。“每观点只说一遍”未引入，论文中的必要回指可以保留。平台报告 3.2.8 与包内自报 3.3.0 不一致，分别记载，不声称拿到某一统一版本。

未采用公文固定栏目、号召结尾、模板分值、重写阈值或新的文风禁词清单；没有为这些语义判断补 Python 工程门禁。

## 未解决与归因范围

模型仍可能跳页、过度索要材料、附加流程前言、在评审建议中添事实。最终 N2 的 Qwen 仍保留外围否定；MiniMax 删去手续等尾句，却推定“样本来自单一机构”，题面“没有跨机构样本”本身不保证这一归属。这种错误在多个基线/候选已有，不能按本次恢复旧否定段单独归因，也不能从记录中删除。

本轮合入的是可审查的路由和角色协作修补、段落范围协议以及 Python 维护职责修正，不是全模型优胜宣言。多个阶段是不同冻结候选，不能拼成一个单一 A/B 胜率。没有进行真实跨项目数十章论文、所有宿主客户端或 WorkBuddy 实装测试；也没有更新发布渠道。
